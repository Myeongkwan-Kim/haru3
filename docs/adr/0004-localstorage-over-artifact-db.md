# 0004. 서버 저장 대신 브라우저 로컬 저장을 쓴다

- 상태: 채택
- 날짜: 2026-09-09

## 맥락

Claude Artifact에는 `db` 런타임 기능이 있어 페이지가 서버에 데이터를 저장할 수
있습니다. 2주치 기록이 브라우저 캐시와 함께 날아가는 것을 막으려면 이쪽이
안전합니다.

그런데 `db`를 선언한 아티팩트는 **조직 내부 전용이 되어 조직 밖 사람은 페이지를
열 수 없습니다.** 실사용자는 조직 구성원이 아닙니다.

## 결정

`db`를 쓰지 않습니다. `localStorage`(키 `haru3.v1`)에만 저장하고, 데이터 탭에서
CSV·JSON으로 복사해 내보내는 경로를 둡니다.

## 근거

실사용자가 열 수 없는 안전한 저장소보다, 열 수 있는 불안한 저장소가 낫습니다.
2주 파일럿의 목적은 데이터 파이프라인을 만드는 것이 아니라 교사가 실제로 이
도구를 쓰는지 관찰하는 것입니다.

## 결과

- **브라우저 데이터를 지우면 기록이 사라집니다.** 며칠에 한 번 내보내는 습관이
  필요하고, 이것은 사람이 지켜야 하는 절차입니다.
- 가져오기 기능이 없다면 내보낸 데이터로 복구할 수 없습니다. 이 점은 검증
  단계에서 다시 판단해야 합니다.
- 아티팩트로 배포하면 열람에 Claude 로그인이 필요합니다. 그래서 `dist/`를
  직접 호스팅하는 경로를 함께 준비했습니다.
