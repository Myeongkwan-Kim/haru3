# 하루 세 아이

유치원 교사가 수업 중 짬에 10초로 남기는 아이 관찰 기록 도구.
2주 파일럿용 프로토타입입니다.

## 설계 전제

- **전수 기록을 하지 않습니다.** 하루에 눈에 띈 아이 2~3명만 남기고,
  기록되지 않은 아이는 결측이 아니라 "평범했다"로 취급합니다.
- **관찰이 일어나는 시간과 기록하는 시간이 다릅니다.** 쉬는 시간에 사건이
  벌어지고 수업 시간에 짬이 나므로, 입력은 언제나 30분~1시간 뒤의 회상입니다.
  그래서 시간대(슬롯) 단위로 기록합니다.
- **사실과 해석을 분리해서 받습니다.** 관찰 태그(무슨 일이 있었나)와
  감정 축(선생님이 본 아이 상태)이 별도 필드입니다. 한 필드에 뭉치면
  나중에 어떤 대시보드로도 편향을 되돌릴 수 없습니다.
- **감정 축은 빨강–초록이 아닙니다.** 파랑(위축)–회색(평소)–앰버(활발)로,
  좋고 나쁨의 가치판단이 덜 실리게 했습니다.
- **첫 화면의 주인공은 점수가 아니라 공백입니다.** 4일 넘게 기록이 없는
  아이를 상단에 올려, 조용해서 눈에 안 띄는 아이가 드러나게 합니다.

## 파일

| 경로 | 용도 |
|---|---|
| `index.html` | **원본.** Artifact 본문 규격이라 `<!doctype>`·`<head>`·`<body>`가 없습니다 |
| `static/` | 부속 파일 원본 — `manifest.json`, `icon.svg`, `sw.js` |
| `build.sh` | 원본을 완전한 HTML 문서로 감싸 `docs/`를 만듭니다 |
| `docs/` | **배포 산출물.** GitHub Pages가 이 폴더를 그대로 서빙합니다 |
| `docs/adr/` | 결정 기록. 산출물이 아니라 문서이므로 빌드가 건드리지 않습니다 |

편집은 `index.html`과 `static/`에만 하고, `./build.sh`로 `docs/`를 다시 만듭니다.
`docs/index.html`을 직접 고치면 다음 빌드에서 덮어써집니다.

## 배포 (GitHub Pages)

저장소 **Settings → Pages → Source**를 **"Deploy from a branch"**,
브랜치 `main`, 폴더 `/docs`로 설정하면 push할 때마다 반영됩니다.

고친 뒤 배포하는 순서:

    ./build.sh && git add -A && git commit -m "설명" && git push

**HTTPS여야 홈 화면 추가와 오프라인 동작이 정상입니다.** GitHub Pages는 기본 HTTPS입니다.

로컬 확인:

    python3 -m http.server 8931 --bind 127.0.0.1 --directory docs

## 아이폰에 설치하는 법 (실사용자에게 전달할 내용)

**반드시 사파리로 열어야 합니다.** 크롬으로 열면 그냥 웹페이지이고,
iOS가 7일간 방문이 없으면 저장된 기록을 지웁니다.

1. 사파리로 링크를 엽니다
2. 아래 공유 버튼(↑) → **"홈 화면에 추가"**
3. 이후에는 홈 화면 아이콘으로만 엽니다

홈 화면 앱으로 쓰면 7일 삭제 규칙에서 제외되지만, 사파리 방문 기록·데이터를
지우면 기록도 함께 사라집니다. **데이터 탭의 백업 버튼으로 며칠에 한 번
카톡에 보내두세요.** 마지막 백업이 5일이 지나면 첫 화면에 배너가 뜹니다.

## 데이터

브라우저 `localStorage`(키 `haru3.v1`)에만 저장됩니다. 서버가 없습니다.

- 브라우저 데이터를 지우면 기록도 사라집니다.
- 데이터 탭에서 CSV/JSON으로 복사해 며칠에 한 번 빼두세요.
- 2주 파일럿이 끝나면 CSV를 DB로 옮겨 대시보드를 만드는 것이 다음 단계입니다.

## 2주 파일럿에서 확인할 것

1. 하루에 실제로 몇 명을 기록하는가 (0명인 날이 며칠인가)
2. 어느 시간대에 기록하는가
3. 이모지·태그만으로 충분한가, 결국 한 줄 메모를 쓰게 되는가
4. "놓치고 있는 아이"를 보고 실제로 그 아이를 기록하러 가는가

이 네 가지 답이 스키마와 다음 버전의 형태를 결정합니다.
